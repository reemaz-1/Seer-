## ما وُجد في الكود قبل التعديل

- صفحة إشعارات العميل تقرأ مجموعة `notifications`، لكن انتقالات طلب الخدمة لم تكن تكتب إشعارات للعميل.
- لا توجد آلية إرسال تقييم أو واجهة نجوم في تفاصيل الطلب المكتمل.

- نموذج الطلب المشترك اختلف بعد إضافة سجل الطلبات؛ نسخة العميل لم تتضمن `cancelledAt` و`OrderStatus.past`.

- إعادة استخدام قناة التنبيه وخدمة Android من كود مقدم الخدمة مع أسماء العميل: صوت/اهتزاز بالمقدمة، وإشعار هاتف في الخلفية. تظهر «نتابع تحديثات طلبك» أثناء وجود طلب نشط فقط. الرجوع يعرض آخر تنبيه فات دون صوت مكرر.

- الضغط على الإشعار يعلّمه مقروءًا ويفتح تفاصيل الطلب. فشل الاتصال يبقي إمكانية إعادة المحاولة.

## ما لم يُتحقق منه بعد

- لم تُجرَ تجربة إنتاجية بحساب عميل ومقدم خدمة حقيقيين على هاتف؛ أُجريت تجربة معزولة على محاكي Android API 35 كما هو موضح أدناه.
- الإشعارات تستخدم طريقة الدانا الموجودة لدى مقدم الخدمة: بانر بصوت/اهتزاز وفق وضع الهاتف في المقدمة، وإشعار نظام عند Home أو قفل الشاشة. خدمة Android تبقي الاستماع قائمًا أثناء وجود طلب نشط وتُوقف عند انتهاء الطلب أو تسجيل الخروج أو سحب التطبيق من Recents. هذا ليس Push بعد إنهاء العملية أو Force stop. أزيلت إضافة FCM ووظائف Cloud Functions بناءً على طلب استخدام طريقة الفريق؛ لا يلزم نشر Functions لهذا التنفيذ.
- بطلب صريح من المستخدم: لا تُنشر قواعد Firestore إلى المشروع الفعلي. ملف القواعد يُرفع إلى GitHub للمراجعة فقط. يجب مراجعة الملف الكامل مع الفريق وتأكيد توافقه مع تغييرات الإدارة والتتبع قبل نشره؛ نشر جزء من القواعد وحده غير كافٍ.
- فحص أوسع أظهر إخفاقًا موجودًا مسبقًا في اختبار رسالة إلغاء الطلب لدى مقدم الخدمة: الاختبار يتوقع نصًا قديمًا بينما الصفحة الحالية تعرض `notification.body`. كما تبقى إخفاقات اختبارات AuthGate القديمة بسبب Firebase غير المهيّأ في اختبارات الواجهات. الملفات المسببة لهذه الإخفاقات لم تدخل ضمن تعديل المهمتين.
- حالة بطاقتي Trello بقيت Under Testing؛ لا تمثل الاختبارات الآلية وحدها اعتمادًا لتجربة الإنتاج.


## تجربة Android بدون هاتف — 2026-11-06

شُغّل APK اختبار على محاكي Android API 35 arm64، مع Auth وFirestore محليين في `demo-seer-alert-preview`. مدخل الاختبار يستخدم نفس controllers وخدمة Kotlin الموجودة بالتطبيق، مع بيانات وهمية محقونة مباشرة. هذه تجربة آلية الإشعارات وليست تدفق قبول طلب كامل من واجهة مقدم الخدمة.

| الحالة | النتيجة المرصودة |
| --- | --- |
| المقدمة | الحدث `host-foreground-183121` استدعى البانر مع `sound=true` |
| Home | سجل Android إشعار `SEER TEST HOME` بعد انتقال Flutter إلى `paused` |
| الشاشة مطفأة | `mWakefulness=Asleep` ثم سجل Android إشعار `SEER TEST LOCK` |
| العودة | أحدث حدث فائت ظهر مع `sound=false` |
| انتهاء الطلب | عدد الطلبات النشطة صفر واختفت `OrderUpdatesService` من سجل الخدمات |

مُنحت صلاحية الإشعارات عبر adb لإعداد المحاكي؛ نافذة طلب الصلاحية لم تختبر. استدعاء الصوت ليس إثبات سماع صوت فعلي. لم تختبر هذه التجربة iOS أو هاتفًا حقيقيًا أو توفير البطارية المطوّل أو قتل العملية أو السحب من Recents. الكودان يوقفان الخدمة في `onTaskRemoved` ويستخدمان `START_NOT_STICKY`؛ لا نعتمد الوصول بعد الإغلاق الكامل.

المقارنة النصية لملفي Kotlin تطابقت مع مقدم الخدمة بعد استبدال أسماء الحزمة والخدمة والقنوات ونصوص الإشعارات فقط. شرط التشغيل هو طلب نشط للعميل مقابل وضع التوفر لمقدم الخدمة.

### إعادة التجربة

```sh

# في Terminal آخر:
cd customer
flutter run -d emulator-5554 -t tool/preview_customer_alerts.dart
```

اضغطي «بدء طلب تجريبي نشط» واسمحي بالإشعارات. جرّبي داخل التطبيق، ثم Home، ثم إطفاء الشاشة. أرسلي حدثًا أثناء الخلفية من جذر المشروع:

